# B2：EX2 实际地址 L0 影子查询

日期：2026-10-12（Asia/Shanghai）。用户授权先观察、运行仿真，评估增加查询口的收益。

## 结论

新增EX2实际地址查询有明确但较小的收益，建议首先考虑**仅LW的查询与转发**。
基线轨迹中可解除57,429个EX2依赖等待周期，其中LW为57,343（99.85025%），
LH为0，字节load为86。完整方案静态理想吞吐提升1.66458%，仅LW为1.66205%。

主要改善的是`LW → LH/LBU`的地址依赖。当前L0填充/作废策略下，
两个最热的字段load `80000da4: lh a2,2(a4)` 和 `80000e5c: lbu s8,0(a4)`
均无缓存命中，因此其后的两个分支等待没有被新查询口覆盖。
若要继续优化这部分，需评估MEM1实际返回数据的提前转发，或另行改变缓存填充策略。

## 安全命中与可解除等待的口径

观察器在与原计时报告相同的pre-NBA时钟沿，直接读取现有L0数组。
地址来自已寄存的`e2_alu_out`；仅统计有效EX2 load、流水线可推进、DRAM范围和自然对齐。
标签命中后保守排除MEM1同字store、WB同字store等待更新/作废L0的情况。
不使用同拍即将写入的缓存填充数据，不增加缓存内容，不模拟更多容量。

按实际load宽度、符号和低位地址格式化数据，与TB DRAM对应字的格式化结果对账。
数据一致性属于观察器校验，不能作为未来硬件的命中判断条件。
本轮守卫后不一致为0，但没有在原始命中上遇到同址store阻止案例，
因此没有验证新实现的全部一致性边界条件。

只有当前实际hazard确实等待该EX2 load，且去掉该原因后没有EX1 load/mul、
其他阶段依赖、DRAM/MDU/CSR停顿、重定向或空ID，才计为可解除周期。
生产者用EX2 PC，消费者用真实ID `d_pc`；消费者之和与可解除周期总数对账。

## 限制与是否值得实施

这是只读基线轨迹中的机会数。实际修改RTL会改变发射顺序、缓存访问和填充时机；
没有模拟这些变化，也没有测量新查询口的综合资源、时序或板测成绩。
所以1.66%是静态估算，不能作为已实现的性能收益。

如果接受约1.7%的潜在提升，新增仅LW的EX2读口是一个有依据的小步改动：
能覆盖本次99.85%的机会，避免把子字提取/扩展加入新转发捕获路径。
当前CPU setup WNS=+0.935ns，新端口仍可能影响缓存映射、扇出及stall路径，需重新实现检查。
若目标是显著提升，当前数据更支持进一步观察普通MEM1返回数据的转发机会。
本次没有实现上述CPU改动。
